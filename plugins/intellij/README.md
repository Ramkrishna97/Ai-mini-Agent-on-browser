# AI Agent Mini for IntelliJ IDEA

Build with `gradle buildPlugin` in this folder. Gradle downloads IntelliJ IDEA Community 2023.1.3 if needed; to build against an installed IDE, pass `-PideaPath="<your IntelliJ installation>"`. Install `build/distributions/*.zip` through **Settings → Plugins → ⚙ → Install Plugin from Disk**. This source targets IntelliJ IDEA 2023.1+.

The native tool-window title bar contains a one-click **Agent / Chat** switch and **New chat** (+) in the corner. The compact toolbar uses icons for **Start**, **Stop**, **Refresh models**, **Load model**, and **Advanced settings**; hover for labels. Stop is disabled until the backend has started. The model selector has a bounded width, leaving room for context and MCP/Web controls on one row when space allows (two rows in narrow windows). Models sort by name by default; **Advanced settings → Sort models** also offers size order. Settings open in a popup without shrinking the chat. A plan appears only when available and expands from its collapsed strip above the conversation.

Thinking levels appear only after the selected Ollama model is resident and advertises the native `thinking` capability. Selecting another model or offloading it hides the control and sends requests with thinking off. Sources whose current adapter cannot verify controllable thinking do not expose a misleading setting.

The full-width composer starts at two lines, grows to four visual lines for longer text, and then scrolls. Its icon sends immediately with **Enter**; **Shift+Enter** inserts a line. **Alt+Enter**, or the queue icon, queues a follow-up without interrupting generation or a pending tool approval. The FIFO queue keeps the model, mode, thinking, and editor context captured when each message was queued. A queued-count button shows pending messages in its tooltip. Failures pause the queue (click that button to resume); **Stop** and **New chat** discard pending messages. Queue contents are in memory only.

Open the **AI Agent Mini** tool window. The plugin uses the current project as the agent workspace and includes a backend snapshot; no app-folder prompt is needed. Ollama and LM Studio models appear before **Start** when their local API servers are running. **Start** prepares and starts the backend from the installed plugin. First start requires Python 3.12+ and may download dependencies. If `start.bat` is already running, the plugin connects to that server and leaves the web UI unchanged. Choose Ollama, a local GGUF file, or the LM Studio API. **Load model** starts Ollama if needed; LM Studio must have its local API server running. Select a context size and click **Load in LM Studio** to load that model explicitly. Choose **Agent** to plan, edit, and run with approval, or **Chat** for answers without tools. Optional LM Studio skill folders and `mcp.json` files can be chosen locally; enable MCP tools to use the latter, and approve each tool call. Enter sends and Shift+Enter inserts a line. **New chat** starts a fresh session; follow-ups reuse the current one. Conversations and project metadata are cleared on backend restart.
